# Kubernetes deployment

Kustomize manifests for the `expenses-tracker` namespace. Replaces the former
single-file `conf.yaml` (and the copies in the `kubeconfig` repo).

```
k8s/
├── base/                     # everything that is environment-independent
│   ├── namespace.yaml
│   ├── backend/              # Deployment + ClusterIP Service + NodePort
│   ├── postgres/             # Deployment + Service + PVC (5Gi)
│   └── redis/                # Deployment + Service + PVC (2Gi)
└── overlays/
    └── prod/                 # + moneymind.fyi Ingress & Certificate, pinned tag
```

The namespace is set by kustomize (`namespace: expenses-tracker`), so no
individual manifest hardcodes it.

## Deploy

```sh
# inspect what would change
kubectl diff -k k8s/overlays/prod

# apply
kubectl apply -k k8s/overlays/prod
```

Render without applying:

```sh
kubectl kustomize k8s/overlays/prod
```

## Secrets

`expenses-tracker-secrets` is intentionally **not** generated by kustomize —
it is created out-of-band so credentials stay out of git. Every workload reads
it via `envFrom.secretRef`.

```sh
cp k8s/secrets.example.env k8s/secrets.env   # gitignored
$EDITOR k8s/secrets.env

kubectl create secret generic expenses-tracker-secrets \
  --namespace expenses-tracker \
  --from-env-file=k8s/secrets.env \
  --dry-run=client -o yaml | kubectl apply -f -
```

Changing the Secret does not restart the pods that read it. Roll them manually:

```sh
kubectl rollout restart deployment -n expenses-tracker \
  expenses-tracker-backend expenses-tracker-redis expenses-tracker-database
```

## Releasing a new backend version

CI (`.github/workflows/build.yml`) reads `version` from `build.gradle.kts` and
pushes `xavierclavel/expenses-tracker-backend:<version>` plus `:latest`.
The deployed tag is pinned in one place — `images.newTag` in
`overlays/prod/kustomization.yaml`. Bump it to match `build.gradle.kts`:

```sh
kustomize edit set image xavierclavel/expenses-tracker-backend=:1.3.4
# or just edit overlays/prod/kustomization.yaml
```

`base/` deliberately references `:latest` so it stays applyable on its own;
prod always pins an explicit tag.

## Notes / known rough edges

- `expenses-tracker-nodeport` (NodePort 30081) is carried over from the previous
  setup. Prod traffic arrives through the Traefik Ingress, so this is only a
  direct-access escape hatch — safe to delete from `base/backend/` if unused.
- No CPU/memory requests or limits are set on any container, matching the
  previous setup. Worth adding before this shares a node with anything else.
- `redis:alpine` is an unpinned tag; postgres is pinned to `17.2`.
- Postgres and Redis run as single-replica Deployments backed by
  `ReadWriteOnce` PVCs. A rolling update can deadlock (new pod waits for a
  volume the old pod still holds). `Recreate` strategy or a StatefulSet would
  be the sturdier shape.
